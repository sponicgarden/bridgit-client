What runs where

  • Timer → bounded camera snapshot → free local change filter → Clef choice → persistent watch tally → HTML card reads tally and state.
  • The phone continues watching with the controller offline; remote model inference still needs internet. Pausing preserves the tally and does not extend expiry.

Controller integration

  • Create the watch and save the returned watch_id. To point the card at it, replace "resource_id":null inside the card's /*RECIPE*/ ... /*END RECIPE*/ block with "resource_id":"<watch_id>" before posting card_request.
  • The no-meal rule fires on the phone at 18:00 local phone time. In the installed package it runs the Dinner check flow (photo of the bowl, Clef says full, eaten from or not in view, then the matching notice); the card's Check bowl now runs the same flow. The flow needs Jev and Clef questions on in Agent permissions (off by default; the install review lists it). In the plain watch it posts the notice directly. To reach an owner who is away from the phone, also read the watch.rule event (callback_url or GET /v1/events) and pass it to the owner's own chat, or use native Pet Monitor's portal (see boundaries).
  • Changes to the watch definition require snapshotting the old tally, stopping it, and recreating; the new watch has a new tally.

Only explicit decision-model/weather requests leave the phone; direct or relay transport still requires a running reachable phone.

Boundaries

  • Public composition is a generic watch, not the native Pet Monitor. It does not inherit native camera selection, dual-model comparisons, pet history/portal, microphone classifier, camera search or feeding.
  • Samples show visible activity only. A missed pet is unknown coverage; cached classifications are reused evidence, not new model observations.
  • A generic watch shows results on the phone itself (cards, speech) and to its controlling agent. A remote web view for the owner exists only for the native Pet Monitor (see https://bridgit.cc/learn/applet-backends.md).

Lifecycle

start

POST /v1/watches with the start example; retain the returned watch_id. Then render/post the card with resource_id.

update

GET state/tally first. To change the definition, export required history, DELETE old watch, POST revised definition. No watch PATCH exists.

pause

POST /v1/watches/{id}/pause with {"paused":true}; resume with false. Confirm user_paused from the returned metadata. Expiry is unchanged.

stop

DELETE /v1/watches/{id}; confirm deleted equals the saved id and watch.ended reason deleted. Archive needed tally BEFORE deletion. Cancel the interaction separately.

Failures and costs

  • Camera locked/busy: record an error gap and retry at a later slot; never classify it as resting.
  • Budget/quota/model failure: inspect recent_checks and watch.ended. The template never turns an unavailable reading into zero episodes.
  • The installed package's Dinner check adds at most 10 paid Clef calls a day (one photo each), whether the 18:00 rule or Check bowl now starts it.
  • At most 10 paid Clef calls an hour for this watch. Worst case, running all day every day, that is about 7,200 photos and $0.76 a month at Clef's ~$0.000105 a photo. That fits the default monthly budget ($1.50, shared by all the phone's agents); budgets differ per account, so read GET /v1/limits and scale max_paid_per_hour to the real value. Unchanged scenes reuse the last answer for free, so real use is usually much lower.
  • Clef's free allowance (about 970 photos a day) is shared by all of Bridgit: keep the change check on and the cap low. Check usage.paid_cost_usd and skipped_over_paid_cap; a quiet scene still refreshes within 900 seconds.

Extensions

  • Use an enrolled lan:<id> camera after grant checks.
  • Tune episode gaps and confidence with labeled samples before interpreting totals.
  • Add a no-water rule ({fewer_than:1, of:"drinking", by:"18:00"}) or a none_for_s rule for long gaps between meals.
