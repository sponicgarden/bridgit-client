What runs where

  • Timer → camera → free local image comparison → watch.matched event → controller inspection or offline status card.
  • model none makes no Jev/Clef calls and establishes a baseline before reporting changes.

Controller integration

  • Receive events, avoid duplicate processing by event ID/sequence, persist meaningful history.
  • Controller model interpretation and alerts are optional integrations, not features of the change filter.

Only explicit decision-model/weather requests leave the phone; direct or relay transport still requires a running reachable phone.

Boundaries

  • A changed image is not an intrusion, person count, danger or proof that something happened outside the frame.
  • The latest state and recent checks are bounded; controller must persist event history it needs.

Lifecycle

start

POST /v1/watches with the start example; retain the returned watch_id. Then render/post the card with resource_id.

update

GET state/tally first. To change the definition, export required history, DELETE old watch, POST revised definition. No watch PATCH exists.

pause

POST /v1/watches/{id}/pause with {"paused":true}; resume with false. Confirm user_paused from the returned metadata. Expiry is unchanged.

stop

DELETE /v1/watches/{id}; confirm deleted equals the saved id and watch.ended reason deleted. Archive needed tally BEFORE deletion. Cancel the interaction separately.

Failures and costs

  • Lights, shadows and movement can trigger changes. Tune sensitivity using known examples.
  • Locked/busy camera is an error gap; first baseline does not count as a change.
  • Free local comparison, no paid calls. Captures use battery and require camera permissions and an unlocked phone for built-in cameras.
